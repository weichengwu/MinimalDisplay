# 显示控制与恢复

## 模块和私有 API

AppKit 负责菜单栏、快捷键和应用生命周期，SwiftUI 负责配置窗口。DisplayCore 负责配置、串行显示事务和恢复，DisplayBridge 动态查找私有类与函数。

- `CGVirtualDisplayDescriptor`、`CGVirtualDisplayMode`、`CGVirtualDisplaySettings`、`CGVirtualDisplay` 用于创建和持有虚拟屏。
- `CGSConfigureDisplayEnabled` 用于在 CoreGraphics 配置事务中启用或停用原显示器。
- 公共 CoreGraphics API 用于枚举在线/活动屏幕、读取模式、设置主屏和排列；ColorSync UUID 用于验证恢复目标。

动态查找可以在接口缺失时报告不可用，但不能保证其他 macOS 版本的兼容性。符号存在后仍需验证创建结果、实际模式和活动状态。

## 手动切换

每条配置代表名称、界面宽高和 HiDPI 开关，列表中未启用的配置不占用显示资源。同时只保留一个活动虚拟屏。

1. 验证配置、私有 API 和恢复进程状态。
2. 保存原显示器身份、排列和开机会话，原子写入恢复记录。
3. 创建目标虚拟屏，核对实际模式，设为主屏。
4. 停用原显示器，并等待在线/活动列表收敛。
5. 新屏就绪后才退役旧虚拟屏；相同且有效的配置不重复创建。

显示事务在独立串行队列执行，创建与释放之间保留稳定等待，虚拟屏至少存活 3 秒后才释放。配置更改只保存，不自动应用。远程客户端连接状态不参与事务。

在线和活动状态取自 `CGGetOnlineDisplayList` 与 `CGGetActiveDisplayList`，避免将无效显示器 ID 的布尔查询错误值误判为仍然活动。

## 分辨率与配置迁移

当前格式 `resolutionVersion: 2` 保存界面分辨率。高清模式的实际像素为宽高各乘以 2，关闭后为 1 倍。校验保证实际宽高不超过 8192。

没有版本号的旧配置保存的是实际像素：读取高清配置时将宽高减半，保留显示效果；奇数旧像素值和未知格式拒绝读取，不做舍入。读取不改写原文件，下一次保存写入格式 2，防止重复迁移。损坏文件不会被静默替换。

## 恢复记录与独立进程

本地目录 `~/Library/Application Support/MinimalDisplay/` 存放配置、恢复记录、互斥锁和心跳。日志限制大小，不联网。

恢复记录包含原显示器 UUID、ID、原点、待恢复屏幕及开机会话标识。禁用后 UUID 可能无法读取，仅在同次开机、已记账、当前离线且没有其他 UUID 占用时允许按保存的 ID 恢复。身份冲突或不同开机时拒绝回退。旧记录通过文件创建/修改时间确认是否属于本次开机。

独立 `MinimalDisplayRecovery` 子进程监控父进程和主线程心跳，不安装 LaunchAgent 或登录项。父进程结束后尝试恢复原屏幕；失败时保留记录并重试。主线程清醒时间超过 12 秒没有心跳时，恢复进程先结束自己的父进程，再恢复显示器，避免并发配置。系统睡眠时间不计入心跳超时。

主程序和恢复进程分别持锁。立即重启会等待正常恢复进程释放锁；自动清理孤儿进程前核对所属用户、App 标识、路径、PID、启动时间和会话，避免结束仍有合法主程序的助手。重复打开会激活已有实例。

正常退出尝试恢复，最多等待 8 秒，成功、失败或超时均结束主程序；再次请求退出直接结束。尚未完成的恢复交给已有恢复进程。

## 故障与边界

CG 配置超时后停止进一步创建或移除虚拟屏，保留恢复记录并尝试恢复。WindowServer 本身卡死时无法保证修复，可能需要注销或重启。

App 恢复显示器排列，不操控其他应用窗口，窗口原位置依赖 macOS。切换后新插入的显示器不自动接管；需要先恢复再手动切换。

## 命令行入口

只读诊断，不启动 GUI、不修改显示设置：

```sh
build/1.0.8/MinimalDisplay.app/Contents/MacOS/MinimalDisplay --diagnose
```

应急恢复会实际更改显示设置，仅在需要且主程序、恢复进程均已退出时由用户执行：

```sh
build/1.0.8/MinimalDisplay.app/Contents/MacOS/MinimalDisplay --restore
```

隔离的恢复进程验证方法见 [CONTRIBUTING.md](../CONTRIBUTING.md)。它不等同于真实关屏或异常恢复验收。
