# 验证记录

此文区分构建、隔离逻辑验证和真实设备验收。当前状态为 **UI 待手测**，不据此承诺所有 macOS 和硬件兼容。

## 1.0.10 列表排序

增加每条配置的上移、下移操作，复用「…」菜单和右键菜单，不新增常驻按钮。列表与菜单栏共同读取同一配置数组，顺序按 JSON 数组持久化，无需迁移。只有原子保存成功后才更新界面中的顺序；失败沿用现有错误提示。只移动配置位置，不改变活动虚拟屏、配置字段或显示事务。

仅执行 `ProfileOrderingTests` 的 3 项非 UI 测试，全部通过：上下移动及重新加载的顺序/字段保留，首末越界与失效 ID 不改文件，写入失败时不发布新顺序且保留原数据。未执行无关显示事务、恢复进程或全量测试。

打包验证范围为 Release 构建、Info.plist、签名、ZIP 完整性及 SHA-256 回读。菜单点击、列表/菜单栏同步、首末禁用、活动配置排序和重开持久化仍为 **UI 待手测**，没有启动 App 或运行 UI 自动化。

## 1.0.9 恢复快捷键

用户确认在 Mac 本地键盘按快捷键无效，同一状态下菜单恢复正常，问题限定在快捷键注册/事件交付链路。检查时运行的已安装 App 为 1.0.7；旧版没有记录注册状态和触发来源，已有恢复日志无法确定按键是否到达。对实际热键组合做短暂独占注册探测（随即注销、不发送按键、不切换显示器），返回成功，不能据此证明旧 App 收到过按键。

本次将处理器安装与热键注册目标从 application target 改为 dispatcher target；增加事件签名/ID 校验、独占注册、失败清理、系统错误码及注册/触发/恢复结果日志。诊断版本从 App Info.plist 读取。没有改变显示恢复事务或新增系统隐私权限。

已执行：Release 编译、Info.plist 与签名检查、ZIP 完整性和 SHA-256 校验。没有能覆盖真实 Carbon 按键交付的现成非 UI 测试，本次不以无关核心测试代替，也不新增仅复述注册参数的测试。未发送模拟按键、启动 UI 或执行真实显示切换。尚未在本机按键复现环境确认改动后的交付结果，具体根因仍未完全证实，状态为 **UI 待手测**。

实现参考：本地 macOS SDK 的 CarbonEvents.h，以及 [Google Toolbox for Mac 的 Carbon dispatcher 实现](https://chromium.googlesource.com/external/github.com/google/google-toolbox-for-mac/+/3c3111d3aefe907c8c0f0e933029608d96ceefeb/AppKit/GTMCarbonEvent.m)。
